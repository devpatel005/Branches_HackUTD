# 05 Data Model

Conceptual tables and reducers for the SpacetimeDB module. Claude Code chooses exact types and indexes. **Money is integer cents in tables.** Every row that belongs to a household carries `householdId`; clients subscribe with a `householdId` filter.

> [!warning] Visibility
> SpacetimeDB tables marked public can be read by any connected client. That's acceptable for this hackathon because all data is mock **and** the only truly private data (fun-money purchases) is never stored here. In Stage 0/2, check whether SpacetimeDB offers per-client row filtering; if so, use it and note it in [[14 Research Notes]].

## Tables

### Household & people
| Table | Key fields | Notes |
|---|---|---|
| `household` | id, joinCode, name, currentMonth (plan month 0 as YYYY-MM), createdAt | |
| `member` | id, householdId, identity, displayName, colorKey (`a`/`b`/…), role (`member`/`agent`), online, lastSeenAt | Agent is a member with role `agent` |
| `assumption` | householdId, savingsRateBps, inflationBps, loanRateBps | Defaults in [[06 Engine Spec#Assumptions]] |

### Baseline & onboarding
| Table | Key fields | Notes |
|---|---|---|
| `transaction` | id, householdId, ownerMemberId, date, amountCents (+ in / − out), counterparty, counterpartyType | Mock PNC-style data. **Never contains fun-money purchases.** |
| `inferred_item` | id, householdId, ownerMemberId, kind (`income`/`fixed`/`debt`/`retirement`/`external_account`/`flexible`), label, monthlyCents, status (`pending`/`confirmed`/`edited`/`rejected`) | Produced by inference ([[06 Engine Spec#Baseline inference]]) |
| `gap_question` | id, householdId, ownerMemberId, prompt, answerType (`range`/`choice`/`number`), options, answer | Only for gaps inference can't fill |
| `baseline` | householdId, incomeCentsByMember, fixedCents, debtCents, flexibleCents, retirementCents, liquidSavingsCents | Derived from confirmed items; recomputed by reducer |
| `fun_money` | householdId, memberId, monthlyCents, status (`within`/`over`), carryoverCents | Amount and status only |

### Plan
| Table | Key fields | Notes |
|---|---|---|
| `goal` | id, householdId, title, icon, costTodayCents, targetMonth (plan-month index), priority (`must`/`flex`), createdBy, status (`active`/`completed`) | |
| `plan_projection` | householdId, version, json | Engine output for the committed plan: monthly series (yearly samples for UI), per-goal results, stats, provenance. Recomputed on every plan change |

### Events, impact, branches
| Table | Key fields | Notes |
|---|---|---|

| `impact` | eventId, json | Engine output: at-risk goals, shortfalls, tight months/years, emergency fund before/after |
| `branch_candidate` | id, eventId, sessionId, batch, levers (json), stats (json), source (`engine`/`bridge`/`custom`), shownAt | Generated by engine; stable ordering |

### Live session
| Table | Key fields | Notes |
|---|---|---|

| `session_member` | sessionId, memberId, present, selectedBranchId, ready, readyAt | Presence, picks, ready check |
| `reaction` | sessionId, memberId, branchId, emoji | One per member per branch (latest wins) |

### Agent
| Table | Key fields | Notes |
|---|---|---|

| `agent_job` | id, householdId, kind, input (json), status (`queued`/`running`/`done`/`failed`), progressText, result (json), attempts, modelUsed | The bus between app and agent |

## Reducer groups
- **Household:** `createHousehold`, `joinHousehold`, `setDisplayName`, lifecycle connect/disconnect → presence.
- **Onboarding:** `seedMockData(profileId)` (dev/demo), `runInference`, `confirmItem`, `editItem`, `rejectItem`, `answerGap`, `setFunMoney`, `setFunMoneyStatus`.
- **Plan:** `addGoal`, `editGoal`, `removeGoal`, `setAssumptions`, `recomputeProjection` (internal, called by the others).
- **Events:** `createEvent`, `answerEventParam`, `computeImpact`, `dismissEvent`.
- **Branches:** `generateCandidates`, `tuneLever` (slider), `addConstraint`, `removeConstraint`, `reroll`, `requestBridge`.
- **Session:** `startSession`, `joinSession`, `selectBranch`, `react`, `setReady`, `leaveSession`; commit happens inside `setReady` when all members are ready.
- **Chat/agent:** `sendMessage` (queues jobs), and agent-only: `claimJob`, `setJobProgress`, `completeJob`, `failJob`, `postAgentMessage`, `nameBranches`, `applyEventInterpretation`, `applyConstraintTranslation`.

## Rules
- Any reducer that changes goals, assumptions, baseline, or the committed plan calls `recomputeProjection`.
- Agent-only reducers reject callers whose member role isn't `agent`.
- Plan-changing reducers reject callers whose role is `agent` (the agent proposes; humans decide).
- Committing a branch applies its levers to goals/baseline, marks the event `applied`, and recomputes the projection, all in one transaction.
